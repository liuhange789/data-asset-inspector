## 二、部署步骤

### 2.1 获取代码

将交付的 DeepSeek-Harness 文件夹复制到目标服务器，或通过U盘/内网共享方式传输。如使用Git管理，可自行初始化仓库。

### 2.2 安装依赖

```bash
# 安装所有依赖包
pnpm install
```

**预期输出：** `Done in XXs`，无错误信息。

### 2.3 配置环境变量

在项目根目录创建 `.env` 文件：

```bash
# DeepSeek API Key（必填）
DEEPSEEK_API_KEY=sk-您的API密钥

# DeepSeek API 基础地址（可选，留空使用官方默认地址）
# DEEPSEEK_BASE_URL=https://api.deepseek.com
```

> **安全提示：** `.env` 文件已被 `.gitignore` 忽略，不会提交到代码仓库。请勿将 API 密钥硬编码在代码中。

### 2.4 配置商业规则

编辑 `config/business-rules.json` 文件，根据客户业务场景定制：

```json
{
  "version": "1.0",
  "sensitivePatterns": {
    "idCard": {
      "pattern": "[1-9]\\d{5}(18|19|20)?\\d{2}(0[1-9]|1[2])(0[1-9]|[12]\\d|3[01])\\d{3}[\\dXx]",
      "level": "FULL"
    },
    "phone": {
      "pattern": "1[3-9]\\d{9}",
      "level": "PARTIAL"
    }
  }
}
```

**可配置项说明：**

| 配置块 | 说明 | 修改影响 |
|--------|------|----------|
| `sensitivePatterns` | 敏感字段识别规则和脱敏级别 | 新增/修改敏感字段类型 |
| `maskingLevels` | 脱敏策略定义 | 修改脱敏处理方式 |
| `cleaningRules` | 数据清洗规则和质量阈值 | 修改清洗标准和质量评级 |
| `valueAssessment` | 数据价值评估关键词和评级 | 修改价值评估标准 |
| `compliance` | 合规政策引用 | 修改合规声明依据 |
| `packaging` | 包装规则、合规声明、定价建议 | 修改产品说明书内容 |

### 2.5 构建项目

```bash
# 构建全部（主机库 + 客户端库 + Web前端）
pnpm run build
```

**分步构建（如需）：**

```bash
pnpm run build:lib:host    # 仅构建主机端库
pnpm run build:lib:client  # 仅构建客户端库
pnpm run build:web         # 仅构建Web前端
```

**预期输出：** 所有包 `Build complete`，无 TypeScript 错误。

### 2.6 验证部署

```bash
# 运行类型检查
pnpm run typecheck

# 运行单元测试
pnpm run test
```

**预期结果：** 类型检查0错误，101个测试全部通过。

## 三、运行方式

### 3.1 Web 界面模式（推荐）

适用于交互式操作，通过浏览器使用。

```bash
# 启动 Web 服务（加载数据资产化插件）
pnpm dsh web --patch ./packages/data-asset/cordis.yml
```

**访问地址：** `http://127.0.0.1:3080`

**使用步骤：**
1. 在浏览器中打开上述地址
2. 在对话框中输入处理请求，例如：
   > 请对 D:\data\sales.csv 执行完整的数据资产化处理流程
3. 系统自动执行脱敏→清洗→盘点→包装四步流程
4. 查看返回的处理报告和生成的文件

### 3.2 Headless 命令行模式

适用于自动化批处理和脚本调用。

```bash
# 单次执行任务
pnpm dsh --profile headless --patch ./packages/data-asset/cordis.yml "请对 D:\data\sales.csv 执行完整的数据资产化处理流程"
```

**特点：** 执行完毕后自动退出，适合定时任务或CI/CD流水线集成。

### 3.3 单插件独立使用

各插件可独立调用，适用于只需要单一功能的场景：

| 需求 | 对话指令 |
|------|----------|
| 仅脱敏 | "请对 D:\data\sales.csv 进行脱敏处理，策略为PARTIAL" |
| 仅清洗 | "请对 D:\data\sales.csv 进行数据清洗" |
| 仅盘点 | "请盘点 D:\data 目录下的数据资产" |
| 仅包装 | "请将 D:\data\cleaned.csv 打包为数据产品，产品名称为'销售数据产品'" |

## 四、运维管理

### 4.1 日志管理

**审计日志位置：** 控制台标准输出

**日志格式：**
```
[插件名] 时间戳 | 操作: 操作名 | 操作人: system | 输入: 路径 | 输出: 路径 | 结果: SUCCESS/FAIL
```

**日志保存建议：**
- 生产环境建议将控制台输出重定向到文件：`pnpm dsh web --patch ... > logs/dsh.log 2>&1`
- 或使用进程管理工具（如 PM2）自动管理日志轮转

### 4.2 数据备份

| 备份对象 | 路径 | 建议 |
|----------|------|------|
| 商业规则配置 | `config/business-rules.json` | 每次修改后备份 |
| 处理产出数据 | 项目根目录下的 `_masked.csv`、`_cleaned.csv` | 定期归档 |
| 产品说明书 | `*_产品说明书.txt` | 随数据一同归档 |
| 会话记录 | `.sessions/` 目录 | 按需备份 |

### 4.3 性能调优

| 场景 | 调优建议 |
|------|----------|
| 大文件处理（>100MB） | 增加Node.js内存限制：`node --max-old-space-size=4096` |
| 批量处理多文件 | 使用Headless模式编写批处理脚本 |
| 并发处理 | 启动多个Headless实例并行处理不同文件 |
| Web响应慢 | 检查网络延迟和API Key配额 |

### 4.4 常见问题处理

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 启动报错 `Cannot find module` | 依赖未安装或未构建 | 运行 `pnpm install && pnpm run build` |
| 启动报错 `frontend dist not built` | Web前端未构建 | 运行 `pnpm run build:web` |
| API调用失败 | API Key无效或过期 | 检查 `.env` 文件中的 `DEEPSEEK_API_KEY` |
| 脱敏不生效 | 敏感字段正则不匹配 | 检查 `business-rules.json` 中的正则表达式 |
| 中文路径乱码 | PowerShell编码问题 | 确保终端使用UTF-8编码 |
| 插件未加载 | cordis.yml中插件路径配置不正确，或--patch参数未指向正确的cordis.yml文件 | 确认cordis.yml中的插件路径为绝对路径，并检查--patch参数是否正确指向 ./packages/data-asset/cordis.yml |

### 4.5 版本更新

```bash
# 拉取最新代码
git pull origin main

# 重新安装依赖
pnpm install

# 重新构建
pnpm run build

# 验证
pnpm run typecheck && pnpm run test
```

## 五、安全注意事项

### 5.1 API 密钥安全

- **禁止**将 API 密钥提交到代码仓库
- **禁止**在日志中打印 API 密钥
- `.env` 文件权限设置为仅所有者可读（Linux: `chmod 600 .env`）
- 定期轮换 API 密钥

### 5.2 数据安全

- 原始数据文件建议存放在受限目录，仅授权人员可访问
- 脱敏后的数据方可对外共享或传输
- 审计日志保留期限不少于6个月（按合规要求）
- 生产环境建议启用磁盘加密

### 5.3 网络安全

- Web服务默认监听 `127.0.0.1:3080`（仅本地访问）
- 如需远程访问，配置反向代理（Nginx）并启用HTTPS
- 建议在内网环境部署，不建议直接暴露到公网
